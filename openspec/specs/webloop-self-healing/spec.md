# webloop-self-healing Specification

## Purpose
Provide lenient, self-healing AST JSON auto-repair, streaming thinking deltas, schema-aware path/line resolution, and multi-schema parsing for web models and text-based tool emulation in AMUX.
## Requirements
### Requirement: Lenient AST JSON auto-repair for Web tool calls
The tool execution engine SHALL automatically repair malformed JSON arguments (including unbalanced braces, trailing commas, unescaped quotes, unescaped raw newlines) generated by web chat sessions before returning validation errors to the client, and SHALL parse bracket-formatted tool calls from conversation history. The engine SHALL also support lenient multi-schema parsing across Gemini parameters, OpenAI function arguments (object or stringified), flat JSON, and LangChain action/action_input formats.

#### Scenario: Auto-repair unclosed JSON braces
- **WHEN** a web model generates `<tool_call>{"name":"Bash","arguments":{"command":"ls -la"` without closing braces
- **THEN** the self-healing parser automatically completes the JSON structure and emits a valid tool call

#### Scenario: Parse bracket tool calls matching conversation history
- **WHEN** a web model generates `[Tool call: Bash id=1] {"command":"ls"}` or `[tool_call: Bash] {"command":"ls"}`
- **THEN** the parser recognizes the tool call, extracts the arguments, and strips the markup from the user-facing text stream

#### Scenario: Lenient parsing of Gemini parameters schema
- **WHEN** a web model outputs tool arguments under `"parameters"` instead of `"arguments"`
- **THEN** the parser extracts the parameters and normalizes them into the canonical tool call

#### Scenario: Lenient parsing of OpenAI function wrapper schema
- **WHEN** a web model wraps tool calls in `"function": {"name": "...", "arguments": ...}` with object or stringified JSON arguments
- **THEN** the parser extracts the function name and unmarshals the arguments into the canonical tool call

#### Scenario: Lenient parsing of flat JSON format
- **WHEN** a web model places tool argument keys alongside `"name"` at root level without an arguments wrapper
- **THEN** the parser preserves all extra root-level keys as tool arguments

#### Scenario: Lenient parsing of LangChain action format
- **WHEN** a web model uses `"action"` and `"action_input"`
- **THEN** the parser maps `"action"` to tool name and parses `"action_input"` as tool arguments

#### Scenario: Transparent retry on unrecoverable tool call failure
- **WHEN** a web session generates completely unparseable text instead of requested tool markup
- **THEN** the gateway initiates an immediate transparent retry or failovers to the next provider in pool within 1.5 seconds without dropping the SSE stream

### Requirement: Streaming Thinking Deltas & Speculative Keepalive
The web stream wrapper SHALL immediately stream reasoning/thinking deltas (`ch.Thinking` and `<thought>` blocks) to the client IDE while buffering and validating candidate tool calls.

#### Scenario: Thinking block streamed without blocking
- **WHEN** a web model generates thinking tokens before an eventual tool call
- **THEN** the thinking tokens are immediately forwarded to the client IDE SSE stream so progress indicators remain active

### Requirement: Schema-Aware Path and Line Number Auto-Resolution
The gateway tool engine SHALL automatically convert relative file paths to absolute paths for strict tools (`AbsolutePath`) and compute valid line ranges (`StartLine`, `EndLine`) bounded by the actual file content on disk.

#### Scenario: Auto-resolve relative file path for AGY tools
- **WHEN** a model emits `{"AbsolutePath": "main.go"}` for an AGY tool
- **THEN** the tool engine resolves it to the absolute file path on disk

#### Scenario: Bound EndLine to file line count
- **WHEN** a model omits `EndLine` for `replace_file_content`
- **THEN** the tool engine inspects the file on disk, locates `TargetContent` lines, and bounds `EndLine` within the file's line count instead of using an unbounded value
